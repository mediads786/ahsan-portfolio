Verified workflow integration

Keep accepted orders safe, prevent duplicate processing, and make failed ERP deliveries visible and recoverable.

Authenticated Shopify orders are stored in PostgreSQL, then delivered through n8n with scheduled retries, dead-letter recovery and an audit trail. Gmail and WhatsApp alerts keep operators informed when delivery fails.

  • Real Shopify → Odoo. Order #1018 became draft quotation S00048. Replaying the signed webhook created no duplicate.
  • Recovery tested. Concurrent intake, scheduled retries, dead-letter recovery, mock crash reconciliation and restart persistence passed.
  • WhatsApp delivery verified. Meta accepted the custom alert template, and the recipient confirmed receipt.

The default demonstration uses mock ERP. The real Odoo integration was tested separately with a draft quotation; the QA report records the tested scope and remaining limitations.

Architecture and operational scope

Signed Shopify webhook → n8n validation → PostgreSQL atomic intake → scheduled delivery workflow → mock ERP / Odoo QA draft branch

PostgreSQL functions control intake, job claims, lease-checked completion, retries and outboxes. The default worker uses mock ERP. The Odoo QA branch verifies a specific draft-quotation fixture; it does not perform the API implementation’s governed cancellation, stock adjustment or signed shipment operations.

The custom WhatsApp template passed direct API acceptance and user-confirmed phone receipt. That test did not establish a new scheduled-outbox regression. Fresh-instance workflow import, actual backup restore, broader real Odoo faults/concurrent creation and permanent Meta-error handling remain unverified. See the linked QA report for the complete tested scope.
